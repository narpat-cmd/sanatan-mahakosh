PROBLEM JO AB TAK HUI
---------------------------------------------------------------------
Site banti hai par: kuch pages khulte hain, kuch click par kuch nahi
hota, kuch cards/buttons dead hain, search mein sab nahi aata. Yani
code "likha" gaya par kabhi asli browser mein chala kar check nahi hua.

IS PART KA RULE: Ab "done" tabhi bolna jab browser mein khud chala kar
dikha do ki har click kaam karta hai. Sirf code padhkar "sahi hai"
bolna MANA hai.

---------------------------------------------------------------------
RULE 1 — PEHLE TEST KARO, PHIR BANAO (harness first)
---------------------------------------------------------------------
Kuch naya banane se PEHLE ye 3 tools banao aur chalao:

 A) scripts\check-links.js  (static link checker)
    - Har .html file padho. Har <a href>, <script src>, <link href>,
      <img src>, onclick="location=..." nikalo.
    - Har target file disk par hai ya nahi check karo.
    - Har #anchor / data-id / modal id jo JS use karta hai, HTML mein
      maujood hai ya nahi.
    - Kuch bhi toota ho to list karo aur exit code 1 do.

 B) scripts\click-test.js  (real browser, Playwright/Puppeteer)
    - Har page file:// URL se kholo.
    - Har clickable element (a, button, [onclick], [data-*], .card,
      .book, .temple, tabs, nav, search result) dhundho aur ek-ek
      CLICK karo.
    - Har click ke baad check: URL badla? modal khula? DOM badla?
      Agar kuch nahi hua = DEAD CLICK = FAIL.
    - Console error, 404, uncaught exception = FAIL.
    - Elements jo "visible" hain par kisi aur layer ke neeche hain
      (document.elementFromPoint se pata chalta hai) = BLOCKED = FAIL.
    - Report: page | element | kya expected | kya hua.

 C) scripts\search-test.js
    - Har data entry (har book/adhyay, aarti, mantra, mandir, devta,
      tyohar, sanskar, tradition) ke title se search karo.
    - Result mein wahi entry aani chahiye, aur click par sahi jagah
      khulni chahiye.
    - Koi entry search mein na aaye = FAIL.

 npm run verify  =  check-links + click-test + search-test, teeno.
 Jab tak npm run verify poora PASS na ho, kaam "done" nahi.

---------------------------------------------------------------------
RULE 2 — CLICK KYUN FAIL HOTE HAIN (in sab ko dhoondh kar theek karo)
---------------------------------------------------------------------
 1. Overlay/pseudo-element click rok raha hai (::before/::after,
    full-size absolute/fixed div, bina pointer-events:none).
 2. 3D transform (preserve-3d, perspective, backface-visibility) ki
    wajah se invisible face upar aa gayi.
 3. Script load order galat: code chalta hai par DOM/data tayyar nahi.
 4. Event listener purane element par laga, innerHTML re-render ke
    baad hat gaya. FIX: EVENT DELEGATION (document level par ek
    listener, data-action attribute se).
 5. onclick="fn()" jahan fn global nahi hai.
 6. Naya page/element banaya par uska data file HTML mein include nahi.
 7. id/selector mismatch (HTML mein alag naam, JS mein alag).
 8. file:// par fetch()/ES module/import = silently fail.
 9. Galat relative path (pages root mein, assets styles\ js\ data\ mein).
10. Modal/book reader khulta hai par close/back kaam nahi, ya z-index
    ki wajah se peeche chhup jata hai.
11. CSS display:none / opacity:0 / visibility:hidden animation ke baad
    atka reh gaya.
12. Same page par kai script ek hi global ko overwrite kar rahe hain.

---------------------------------------------------------------------
RULE 3 — EK HI CLICK SYSTEM (kachra mat failao)
---------------------------------------------------------------------
 - Poori site mein ek hi common mechanism: data-action="open-book",
   data-id="..." jaisa. Ek hi js\router.js / js\actions.js sab
   click handle kare (event delegation).
 - Har clickable item ke liye ek hi URL scheme (hash routing ya query):

   Taaki search, bookmark, back button, share sab usi se chalein.
 - Back/forward button sahi kaam kare. Refresh karne par wahi page
   wapas khule.
 - Har data entry ka ek unique stable id ho. Duplicate id = FAIL.
 - Koi bhi "coming soon" jaisa dead button nahi. Jo feature tayyar
   nahi, usko ya to chhupao ya clearly "jald aa raha hai" disabled
   dikhao (aur click test mein ise exception list mein rakho).

---------------------------------------------------------------------
RULE 4 — SEARCH MEIN SAB KUCH AAYE
---------------------------------------------------------------------
 - ONE central registry: data\registry.js (ya build script se auto-

     { id, type, title_sa, title_hi, title_en, aliases[], keywords[],

   type: granth | adhyay | shlok | aarti | chalisa | mantra | stotra |

3. PROBLEM TO SOLVE: DATA SIZE & LOADING
---------------------------------------------------------------------
Currently scriptures.js holds everything in one global. Full
Ramayan (~24,000 shlokas) and Mahabharat (~75,000+ shlokas) will
make one file huge and slow, especially on mobile.

Required architecture: LAZY, PER-CHAPTER LOADING that still works
over file://.

New data layout:

  data\
    scriptures.js              <- small INDEX/MANIFEST only
    scriptures\
      gita\
        meta.js
        ch01.js ... ch18.js
      valmiki-ramayan\
        meta.js
        bal-kand\sarg-001.js ... 
        ayodhya-kand\...
        aranya-kand\...
        kishkindha-kand\...
        sundar-kand\...
        yuddha-kand\...
        uttar-kand\...
      ramcharitmanas\
        meta.js
        bal-kand.js ... uttar-kand.js
      mahabharat\ (18 parvas, chunked per adhyay)
      vedas\ , upanishads\ , puranas\ (same pattern)

Rules for loader:
  - scriptures.js exposes window.SCRIPTURES_DATA as a MANIFEST:
    list of books, each with id, title (sa/hi/en), cover info,
    structure (kands/parvas -> chapters), counts, and file paths.
  - Each chapter file registers itself, for example:
      window.SCRIPTURE_CHUNKS = window.SCRIPTURE_CHUNKS || {};
      window.SCRIPTURE_CHUNKS["gita/ch01"] = { ...chapter data... };
  - Implement a loader in book-reader.js:
      loadChapter(bookId, chapterKey) -> Promise
    It injects a <script> tag (works on file://), waits for onload,
    caches the result, and resolves with the chapter data.
  - Prefetch next chapter while user reads the current one.
  - Show a nice loading state (diya / spinner) while loading.
  - Keep backward compatibility with existing 5 books: migrate
    them into the new layout without losing content.
