3. PROBLEM TO SOLVE: DATA SIZE & LOADING
---------------------------------------------------------------------
Currently scriptures.js holds everything in one global. Full
Ramayan (~24,000 shlokas) and Mahabharat (~75,000+ shlokas) will
make one file huge and slow, especially on mobile.

Required architecture: LAZY, PER-CHAPTER LOADING that still works
over file://.

New data layout:

  data\
    scriptures.js              <- small INDEX/MANIFEST only
    scriptures\
      gita\
        meta.js
        ch01.js ... ch18.js
      valmiki-ramayan\
        meta.js
        bal-kand\sarg-001.js ... 
        ayodhya-kand\...
        aranya-kand\...
        kishkindha-kand\...
        sundar-kand\...
        yuddha-kand\...
        uttar-kand\...
      ramcharitmanas\
        meta.js
        bal-kand.js ... uttar-kand.js
      mahabharat\ (18 parvas, chunked per adhyay)
      vedas\ , upanishads\ , puranas\ (same pattern)

Rules for loader:
  - scriptures.js exposes window.SCRIPTURES_DATA as a MANIFEST:
    list of books, each with id, title (sa/hi/en), cover info,
    structure (kands/parvas -> chapters), counts, and file paths.
  - Each chapter file registers itself, for example:
      window.SCRIPTURE_CHUNKS = window.SCRIPTURE_CHUNKS || {};
      window.SCRIPTURE_CHUNKS["gita/ch01"] = { ...chapter data... };
  - Implement a loader in book-reader.js:
      loadChapter(bookId, chapterKey) -> Promise
    It injects a <script> tag (works on file://), waits for onload,
    caches the result, and resolves with the chapter data.
  - Prefetch next chapter while user reads the current one.
  - Show a nice loading state (diya / spinner) while loading.
  - Keep backward compatibility with existing 5 books: migrate
    them into the new layout without losing content.

4. DATA SCHEMA
---------------------------------------------------------------------
Manifest entry (data\scriptures.js):
  {
    id: "valmiki-ramayan",
    title: { sa: "...", hi: "वाल्मीकि रामायण", en: "Valmiki Ramayana" },
    category: "itihasa",            // veda | upanishad | itihasa | purana | gita | other
    cover: { color, emblem, subtitle },
    languages: ["sa","hi","en"],
    structure: [
      { key: "bal-kand", title: {...}, chapters: 77, files: [...] },
      ...
    ],
    totals: { chapters: 0, verses: 0 },   // filled by verify script
    source: "...", license: "public-domain | cc | permission | original",
  }

Chapter file content:
  {
    book: "valmiki-ramayan",
    section: "bal-kand",
    chapter: 1,
    title: { sa, hi, en },
    verses: [
      {
        n: 1,
        sa: "Sanskrit in Devanagari",
        tr: "IAST/roman transliteration (optional)",
        hi: "Hindi translation (optional)",
        en: "English translation (optional)",
        exp: "explanation (optional)",
        audio: "path or empty",
        source: "...", license: "..."
      }
    ]
  }

For Ramcharitmanas: verse types = doha, chaupai, sortha, chhand,
shloka. Add field type: "doha" | "chaupai" | ... and keep order.

Every translation field must be traceable via source + license.
